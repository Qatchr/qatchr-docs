---
title: "Je eerste API-call"
description: "Haal vacatures op met de juiste organisatiecontext."
---

Je hebt een bereikbare Qatchr API, een access token uit de identiteitsomgeving en het ID van je organisatie nodig. Gebruik een account met `view-vacancies` binnen scope `qatchr`.

<Steps>
  <Step title="Stel de API-origin in">
    Gebruik het domein van jouw deployment. De voorbeeldorigin is een placeholder; de prefix wordt in de calls toegevoegd.

    ```bash
    export QATCHR_ORIGIN="https://api.example.com"
    export QATCHR_TOKEN="<access-token>"
    export QATCHR_ORGANIZATION_ID="<organization-uuid>"
    export QATCHR_USER_ID="<user-uuid>"
    ```
  </Step>
  <Step title="Haal de eerste pagina op">
    ```bash
    curl --request GET       "$QATCHR_ORIGIN/api/v1/vacancies/?offset=0&limit=10"       --header "Authorization: Bearer $QATCHR_TOKEN"       --header "X-Organization-Id: $QATCHR_ORGANIZATION_ID"       --header "X-User-Id: $QATCHR_USER_ID"
    ```

    De JSON-response bevat `results` en `total_count`. Een lege lijst ziet er zo uit:

    ```json
    { "results": [], "total_count": 0 }
    ```
  </Step>
  <Step title="Gebruik de response">
    Bewaar de UUID van de vacature die je nodig hebt. Gebruik de detailcall om die vacature op te halen, of start een sollicitatie met de kandidaat- en vacature-ID.
  </Step>
</Steps>

## JavaScript-voorbeeld

```javascript
const origin = "https://api.example.com";
const response = await fetch(`${origin}/api/v1/vacancies/?offset=0&limit=10`, {
  headers: {
    Authorization: `Bearer ${accessToken}`,
    "X-Organization-Id": organizationId,
    "X-User-Id": userId,
  },
});
if (!response.ok) {
  throw new Error(`Qatchr returned HTTP ${response.status}`);
}
const { results, total_count } = await response.json();
```
